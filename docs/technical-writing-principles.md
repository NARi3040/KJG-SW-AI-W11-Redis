# 문서 작성 원칙

> 이 원칙을 지키면 팀원과 AI가 문서만 읽고 같은 결과를 낼 수 있다. PR에서 바뀐 문서는 AI 리뷰 봇이 이 원칙으로 리뷰한다.

규칙을 기계적으로 적용하지 않는다. 독자가 문서를 이해하고 행동하는 데 방해가 되는지를 본다.

AI가 읽는 리뷰 지침(`.github/docs-review.md`)은 팀 문서가 아니므로 영어로 쓰고, 이 원칙으로 리뷰하지 않는다.

## 모든 문서

### 한 문서에서는 한 주제만 다루기

독자가 한 문서에서 하나의 목적을 달성할 수 있게 한다. 다른 문서에 있는 내용은 복사하지 않고 링크한다. 같은 내용이 두 곳에 있으면 한쪽만 고쳐져 어긋난다.

| 문서 | 다루는 내용 |
|---|---|
| `docs/planning.md` | 공통 계약, 파일 담당, 테스트 색인, 통합 순서 |
| `docs/c-hashtable-and-bindings.md` | C 해시 테이블과 ctypes 연결 |
| `docs/store-and-snapshots.md` | Store, TTL, 스냅샷 |
| `docs/http-and-runtime.md` | HTTP, 큐, 작업자, 시작과 종료 |
| `docs/issues.md` | 작업 단위와 완료 조건 |
| `docs/overview.md` | 요약 |

**Incorrect:** HTTP 문서에 C 함수 원형을 다시 적는다.

**Correct:** HTTP 문서에는 HTTP 계약만 쓰고, 필요하면 `docs/c-hashtable-and-bindings.md`를 링크한다.

### 가치를 먼저 쓰기

문서 첫머리에서 독자가 무엇을 알게 되거나 할 수 있는지 알려 준다.

**Incorrect:** "이 문서는 해시 테이블을 설명한다."

**Correct:** "이 문서를 읽으면 C 해시 테이블의 함수 원형과 확장 규칙을 알고 바로 구현할 수 있다."

### 문체 통일하기

저장소 문서는 "~한다" 문체로 통일한다. 한 문서 안에서 "~해요", "~합니다"를 섞지 않는다.

### 용어와 코드 표기 통일하기

- Store, Runtime, 작업자, Future, 스냅샷처럼 `docs/planning.md`의 용어 표에서 쓰는 이름을 그대로 쓴다. 같은 대상을 다른 이름으로 부르지 않는다.
- 함수, 타입, 필드, 파일 경로, 명령어는 백틱으로 감싼다. (예: `ht_put`, `mini_redis/store.py`, `pytest`)

### 실제와 일치시키기

문서의 명령어, 파일 경로, 링크, 라벨 이름은 저장소에 실제로 있는 것과 같아야 한다. 코드나 설정을 바꾸면 그것을 설명하는 문서도 같은 PR에서 고친다.

## 설계 문서 (`docs/`)

AI는 설계 문서대로 구현하고, 내용이 빠졌으면 구현을 멈춘다. 그래서 설계 문서는 읽는 사람이 추측하지 않고 구현할 수 있어야 한다.

### 테스트 사례 ID를 한 곳에서 정의하기

테스트 사례(T1, S-T3, H2 등)는 한 문서에서만 정의하고, 다른 문서는 ID로 가리킨다. 범위를 적을 때는 `docs/planning.md`의 색인과 맞춘다.

### 입력과 출력을 의미, 형식, 예시로 쓰기

함수의 매개변수와 반환값, 요청과 응답의 필드를 설명할 때는 의미, 허용 형식, 예시를 함께 쓴다. 이름과 타입만 있으면 구현자가 추측해야 한다.

**Incorrect:** `ttl: int`

**Correct:** `ttl: int | None`: 초 단위 수명. `1`에서 `2,147,483,647`까지의 정수이고, 생략하면 무기한이다. (예: `10`)

### 엣지 케이스 적기

빈 키, 빈 값, NUL 바이트, TTL 경계 시각, 해시 충돌, 테이블 확장처럼 경계에 있는 입력을 어떻게 처리하는지 적는다.

### 정하지 않은 내용 드러내기

아직 정하지 않은 내용은 비워 두지 않고 "미정"과 이유를 적는다. 빈칸은 이미 정한 것처럼 보이거나 AI가 임의로 채우게 만든다.

### 필수와 선택 구분하기

과제의 필수 범위와 선택 범위(스냅샷, 복구)를 구분해 적는다. 필수 작업이 선택 작업의 완료를 기다리지 않게 한다.

### 공통 계약 변경 알리기

함수 시그니처, C 상태 코드, HTTP 응답, 파일 형식을 바꾸는 설계는 그 계약을 인용한 다른 문서를 같은 PR에서 고친다.
